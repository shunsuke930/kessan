# 決算対応ダッシュボード

税理士事務所向けの月次タスク自動抽出ツール（Google Apps Script製）。
既存の顧客管理スプレッドシートを読み取り専用で参照し、対象月を指定すると、
その月に対応が必要な会社を自動抽出して一覧表示する。タスクの進捗・コメントは
アプリ専用のシート（既定では `案件タスク` タブ）で管理する。

## ディレクトリ構成

```
src/
  appsscript.json      GASマニフェスト（Webアプリ設定）
  Constants.gs          設定・月次タスク抽出ルール（TASK_RULES）の定義
  DateUtils.gs          日付ユーティリティ
  CustomerService.gs    顧客マスタシートの読み取り（読み取り専用）
  TaskService.gs        タスク用シートのCRUD・月次抽出ロジック
  Code.gs                doGet、クライアントから呼ばれる関数群
  Index.html / Stylesheet.html / JavaScript.html
                         ダッシュボードUI（タスク一覧の表のみ）
```

## セットアップ

### 1. Apps Scriptプロジェクトの作成とpush

```bash
npm install -g @google/clasp
clasp login

# 新規にGASプロジェクトを作る場合
clasp create --title "決算対応ダッシュボード" --type webapp --rootDir src

# 既存のGASプロジェクトに紐づける場合は、生成された .clasp.json の
# scriptId を書き換えるか、.clasp.json.example をコピーして使う
cp .clasp.json.example .clasp.json  # scriptId を実際の値に置き換える

clasp push
```

### 2. スクリプトプロパティの設定

Apps Scriptエディタで「プロジェクトの設定」→「スクリプト プロパティ」から設定する
（`clasp open` でエディタを開ける）。

| プロパティ名 | 必須 | 内容 |
|---|---|---|
| `CUSTOMER_SPREADSHEET_ID` | 必須 | 既存の顧客管理スプレッドシートのID（URLの `/d/` と `/edit` の間） |
| `CUSTOMER_SHEET_NAME` | 任意 | 顧客一覧のシート名。未設定時は先頭シートを使用 |
| `TASKS_SPREADSHEET_ID` | 任意 | タスクデータの保存先スプレッドシートID。未設定時は `CUSTOMER_SPREADSHEET_ID` と同じファイル内に専用タブを作成 |
| `TASKS_SHEET_NAME` | 任意 | タスク用タブ名。既定値 `案件タスク` |

### 3. 顧客マスタの列名の確認・調整

`src/Constants.gs` の `CUSTOMER_COLUMN_ALIASES` は以下の見出し候補を自動検出する：

- 顧客名（法人名・会社名も同じ列として扱う）: `顧客名` / `法人名` / `会社名`
- 決算月: `決算月`
- 決算日: `決算日`
- 担当者: `担当者`

`顧客名`列と、`決算月`または`決算日`のどちらか一方の列があれば動作する
（両方あれば`決算日`を優先し、`決算日`が空の行は`決算月`の末日から自動計算する）。
実際のシートの見出しがこれと異なる場合は、`CUSTOMER_COLUMN_ALIASES` に候補を追加する。

### 4. Webアプリとしてデプロイ

```bash
clasp deploy --description "初回デプロイ"
```

「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択し、
- 実行するユーザー: 「アクセスしているユーザー」
- アクセスできるユーザー: 「全員」（既定。`src/appsscript.json` の `webapp.access` は `ANYONE`）
  - Google Workspaceの組織アカウントで運用しており、組織内のみに限定したい場合は
    `access` を `DOMAIN` に変更した上で「組織内」を選択する。
    ただし個人のGmailアカウント（Workspace未加入）では `DOMAIN` を選ぶと
    「この操作を行う権限がありません」というデプロイエラーになるため、
    その場合は `ANYONE` のままにすること。

を選んで発行する（`src/appsscript.json` の `webapp` 設定に対応）。
「全員」でも、実際にスプレッドシートを読み書きできるのはそのシートを共有されている
メンバーのみ（`executeAs: USER_ACCESSING` のため各自の権限で実行される）。
アクセス範囲の厳密化（ドメイン制限の詳細など）は今後の検討事項。

### 5. 初回の動作確認

デプロイ後、ダッシュボードを開くと自動的に今月のタスク一覧が表示される
（別途「同期」操作は不要 - 表示するたびに、その月に該当する会社の行が
まだ無ければ自動生成される）。

### 6. `TASK_RULES` / タスクシートの列構成を変更したとき（既存データがある場合）

`TASK_HEADERS`（`TaskService.gs`）や `TASK_RULES`（`Constants.gs`）を変更しても、
既に生成済みの行はそのまま残る（列が増減していると見出しがズレる）。
Apps Scriptエディタで `TaskService.gs` の `resetAllTasks` 関数を選択し、上部の
実行ボタン（▷）で1回だけ手動実行すると、`案件タスク` シートのデータ行を全消去し、
ヘッダー行も現在の `TASK_HEADERS` の内容に書き直す。その後ダッシュボードを開けば
新しい定義で作り直される。**入力済みの進捗・コメントもすべて消えるので注意。**
Web UIには意図的に出していない（誤操作で全データを消せてしまうため）。

## 主要ロジックのメモ

- **月次タスク抽出ルール**（`Constants.gs` の `TASK_RULES`）: このアプリは
  「月初にその月に対応が必要な会社を自動で一覧化する」ためのツールで、顧客ごとの
  決算サイクル全体を追うのではなく、対象月ごとに独立してリストを作る。各ルールは
  対象月から見て顧客の決算月が何ヶ月ずれているか（`monthOffset`）で対象を抽出する。
  - **申告準備**（`monthOffset: 1`）: 決算月が対象月の1ヶ月後の会社（決算日の
    1ヶ月前 = 準備を始めるタイミング）
  - **申告・納税**（`monthOffset: -2`）: 決算月が対象月の2ヶ月前の会社
    （日本の法人税申告・納税期限＝決算日から2ヶ月後、が対象月に来る）
  - **納税予想**（`monthOffset: 6`）: 決算月が対象月の6ヶ月後の会社
    （決算日の6ヶ月前＝事業年度のほぼ中間点。中間納付の見込みを立てる想定）
  - 判定は決算「月」のみで行う（`getMonthlyMatches_` in `TaskService.gs`）。日付は
    表示用の決算期（20XX年X月期）を出すためだけに使う。
- **対象月の指定**: ダッシュボード右上の「対象月」欄（`<input type="month">`）で
  yyyy-MM形式の月を選ぶ。過去・未来どちらの月も表示でき、未指定時は実際の今月を使う。
  `getMonthlyTaskList` / `saveTaskUpdate` / `saveTaskUpdatesBatch`（`Code.gs`）が
  それぞれ `referenceMonthIso` 引数を受け取る。
- **表示するたびに自動生成**（`getMonthlyTasks_` in `TaskService.gs`）: 以前のバージョン
  にあった「スプレッドシートと同期」ボタンは廃止した。`getMonthlyTaskList` を呼ぶ
  たびに、その対象月に一致する会社の行がまだ無ければ自動的に追加してから返すため、
  同期を意識する必要がない。複数人が同時に同じ月を開いても、`LockService` で
  排他制御しているため行が重複生成されることはない。
- **タスク一覧**（`renderActionPanel` in `JavaScript.html`）: 対象月に一致した
  タスクを、スプレッドシートの一覧表に近い、1行1タスクの密な表で表示する
  （タスク/クライアント名/決算期/担当者/ステータス/コメント）。
  - 列見出し下のプルダウン（タスク・クライアント名・決算期・担当者・ステータス）
    で絞り込める。決算期の選択肢は日付順（文字列順ではない）で並ぶ
    （`uniqueFiscalPeriods` in `JavaScript.html`）。
  - 決算期列には、その案件の決算年月を「20XX年X月期」の形式で表示する
    （`formatFiscalPeriod` in `JavaScript.html`）。
  - ステータス列は編集可能なプルダウンで、選択するとその場で保存される
    （未着手=グレー/対応中=オレンジ/完了=濃紺の色付き）。
  - 担当者は名前ごとに色分けしたチップで表示（読み取り専用。担当者は顧客マスタ側の
    情報で、タスク単位では変更できないため）。
  - コメント欄は自由入力で、入力するたびに自動保存される（保存タイミングは後述の
    バッチ保存を参照。フォーカスを外さなくても、入力が一定時間止まれば保存される）。
  - 行の色分け（`rowStatusClass` in `JavaScript.html`）: ステータスが完了の行は
    グレーアウトする（`row-done`）。対象月が実際の今月より過去で、かつ未完了の行は
    薄い赤で示す（`row-overdue` - 過去の月の一覧を開いたときに、対応漏れがひと目で
    わかるようにするための表示）。両方の条件を満たす場合は完了が優先される。
  - 現在のフィルター条件に一致するタスクが0件になっても、表自体（列見出しの
    プルダウン）は表示したままにする。0件は本文エリアのメッセージ
    （「該当するタスクはありません」）だけで示すので、フィルターを変更して
    元に戻すことができる。
- **インライン編集のバッチ保存**（`queueTaskUpdate` / `flushPendingUpdates` in
  `JavaScript.html`、`saveTaskUpdatesBatch` in `Code.gs`、`updateTasksBatch_` in
  `TaskService.gs`）: タスク一覧のステータス・コメントを編集するたびに個別に
  サーバーへ送信して画面全体を「更新中」で覆う、という以前の挙動をやめ、変更を
  いったんブラウザ側にためておき（画面には即座に反映される）、入力が1秒止まった
  タイミングでまとめて1回のリクエスト（`saveTaskUpdatesBatch`）で送信するように
  している。複数行・複数項目を続けて編集しても、サーバーへの往復は1回にまとまる。
  画面右上の「未保存の変更があります…」「保存中…」「保存しました」の表示で
  保存状況を確認できる。基準月の変更やページを閉じる直前には、たまっている変更を
  先に送信してから次の処理に進む。
- **重複データの手動クリーンアップ**（`deduplicateTasks` in `TaskService.gs`）:
  何らかの理由でタスクが重複してしまった場合に、Apps Scriptエディタの関数選択
  プルダウンで `deduplicateTasks` を選び、上部の実行ボタン（▷）で1回だけ手動実行
  する。同じ案件・タスク・対象月の行が複数あれば、最初の1件だけ残して残りを
  削除する（`resetAllTasks` と違い、残す行の進捗・コメントはそのまま保持される）。
- **デプロイ確認用のバージョン表示**（`APP_VERSION` in `Constants.gs`）:
  画面最下部に表示される「バージョン: yyyy-mm-dd.n」は、コード変更のたびに
  更新される目印。このアプリはGitHub上のコードを直接実行しているわけではなく、
  Apps Scriptエディタに貼り付けた内容がそのまま動くため、ファイルの貼り替えが
  一部抜けていると、修正したはずの不具合が「直っていない」ように見えることが
  ある。動作がおかしいときは、まず画面最下部のバージョンが、渡された手順書の
  バージョンと一致しているか確認し、一致していなければ該当ファイルを貼り直す。

## ローカル開発

`clasp push` で `src/` 配下の `.gs` / `.html` / `appsscript.json` のみが同期される
（`.claspignore` 参照）。Claude Codeでコードを編集し、`clasp push` でGASに反映する運用を想定。
