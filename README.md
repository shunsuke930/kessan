# 決算対応ダッシュボード

税理士事務所向けの決算対応スケジュール可視化ダッシュボード（Google Apps Script製）。
要件は `要件定義書.md` を参照。既存の顧客管理スプレッドシートを読み取り専用で参照し、
タスク・進捗はアプリ専用のシート（既定では `案件タスク` タブ）で管理する。

## ディレクトリ構成

```
src/
  appsscript.json      GASマニフェスト（Webアプリ設定）
  Constants.gs          設定・タスクテンプレート・色分け閾値・年間マイルストン定義
  DateUtils.gs          日付ユーティリティ
  CustomerService.gs    顧客マスタシートの読み取り（読み取り専用）
  TaskService.gs        タスク用シートのCRUD・テンプレートからの自動生成
  StatusService.gs      通常/要注意/遅延の判定ロジック
  AnnualService.gs       年間カレンダービュー（準備期間/決算期間/マイルストン）のデータ生成
  Code.gs                doGet、クライアントから呼ばれる関数群
  Index.html / Stylesheet.html / JavaScript.html
                         ダッシュボードUI（Frappe Ganttでガントチャート表示）
```

## セットアップ

### 1. Apps Scriptプロジェクトの作成とpush

```bash
npm install -g @google/clasp
clasp login

# 新規にGASプロジェクトを作る場合
clasp create --title "決算対応ダッシュボード" --type webapp --rootDir src

# 既存のGASプロジェクトに紐づける場合は、生成された .clasp.json の
# scriptId を書き換えるか、.clasp.json.example をコピーして使う
cp .clasp.json.example .clasp.json  # scriptId を実際の値に置き換える

clasp push
```

### 2. スクリプトプロパティの設定

Apps Scriptエディタで「プロジェクトの設定」→「スクリプト プロパティ」から設定する
（`clasp open` でエディタを開ける）。

| プロパティ名 | 必須 | 内容 |
|---|---|---|
| `CUSTOMER_SPREADSHEET_ID` | 必須 | 既存の顧客管理スプレッドシートのID（URLの `/d/` と `/edit` の間） |
| `CUSTOMER_SHEET_NAME` | 任意 | 顧客一覧のシート名。未設定時は先頭シートを使用 |
| `TASKS_SPREADSHEET_ID` | 任意 | タスクデータの保存先スプレッドシートID。未設定時は `CUSTOMER_SPREADSHEET_ID` と同じファイル内に専用タブを作成 |
| `TASKS_SHEET_NAME` | 任意 | タスク用タブ名。既定値 `案件タスク` |

### 3. 顧客マスタの列名の確認・調整

`src/Constants.gs` の `CUSTOMER_COLUMN_ALIASES` は以下の見出し候補を自動検出する：

- 顧客名（法人名・会社名も同じ列として扱う）: `顧客名` / `法人名` / `会社名`
- 決算月: `決算月`
- 決算日: `決算日`
- 担当者: `担当者`

`顧客名`列と、`決算月`または`決算日`のどちらか一方の列があれば動作する
（両方あれば`決算日`を優先し、`決算日`が空の行は`決算月`の末日から自動計算する）。
実際のシートの見出しがこれと異なる場合は、`CUSTOMER_COLUMN_ALIASES` に候補を追加する。

なお、当初の要件定義書では「法人名」「担当税理士」も別列として想定していたが、
運用上「顧客名＝法人名」で重複するため統合し、「担当税理士」列は使わない方針に変更した。

### 4. Webアプリとしてデプロイ

```bash
clasp deploy --description "初回デプロイ"
```

「デプロイ」→「新しいデプロイ」→種類「ウェブアプリ」を選択し、
- 実行するユーザー: 「アクセスしているユーザー」
- アクセスできるユーザー: 「全員」（既定。`src/appsscript.json` の `webapp.access` は `ANYONE`）
  - Google Workspaceの組織アカウントで運用しており、組織内のみに限定したい場合は
    `access` を `DOMAIN` に変更した上で「組織内」を選択する。
    ただし個人のGmailアカウント（Workspace未加入）では `DOMAIN` を選ぶと
    「この操作を行う権限がありません」というデプロイエラーになるため、
    その場合は `ANYONE` のままにすること。

を選んで発行する（`src/appsscript.json` の `webapp` 設定に対応）。
「全員」でも、実際にスプレッドシートを読み書きできるのはそのシートを共有されている
メンバーのみ（`executeAs: USER_ACCESSING` のため各自の権限で実行される）。
アクセス範囲の厳密化（ドメイン制限の詳細など）は今後の検討事項。

### 5. 初回のタスク生成

デプロイ後、ダッシュボード右上の「スプレッドシートと同期」ボタンを押すと、
顧客マスタの各社について、現在の決算サイクル分のタスクがテンプレートから自動生成される。
既に生成済みの決算サイクルはスキップされるため、何度実行しても重複生成されない。

### 6. `TASK_TEMPLATE` を変更したとき（既存データがある場合）

`ensureTasksForCustomer_`（`TaskService.gs`）は「その案件・決算サイクルにタスクが
1件でもあれば何もしない」という判定のため、`TASK_TEMPLATE` を書き換えても、
**既に同期済みの案件のタスクは自動更新されない**（新しいテンプレートが適用されるのは、
まだ一度も同期していない案件・決算サイクルだけ）。

古いテンプレートで生成済みのタスクを一新したい場合は、Apps Scriptエディタで
`TaskService.gs` の `resetAllTasks` 関数を選択し、上部の実行ボタン（▷）で1回だけ
手動実行する（`案件タスク` シートのデータ行を全消去し、ヘッダー行も現在の
`TASK_HEADERS` の内容に書き直す。列が増減している場合の見出しズレもこれで解消する）。
その後ダッシュボードで「スプレッドシートと同期」を押せば、新しいテンプレートで
生成し直される。**入力済みの進捗・コメントもすべて消えるので注意。**
Web UIには意図的に出していない（誤操作で全データを消せてしまうため）。

このタイミングで `Constants.gs` も必ず最新版に差し替えておくこと
（`resetAllTasks` はデータを消すだけで、`TASK_TEMPLATE` の中身自体は
`Constants.gs` の記述に従うため、そちらが古いままだと結局同じ内容で
再生成されてしまう）。

## 主要ロジックのメモ

- **タスクテンプレート**（`Constants.gs` の `TASK_TEMPLATE`）: 案件ごとに5件のサブタスク
  （問い合わせ先への事前連絡・貸借対照表資料作成・申告書作成・確認承認取得・申告納税）
  を生成する。各サブタスクは `phase`（`preparation`=決算準備 / `settlement`=申告・納税）
  でどちらかの大区分に紐づいており、これがタスク一覧の「フェーズ」列・フィルターの単位
  になる（個々のサブタスク名は「タスク」列・フィルターで絞り込む）。決算準備に属するのは
  「問い合わせ先への事前連絡」のみで、それ以外の4件は申告・納税に属する。
  同じフェーズに属するサブタスクは全て同じ「開始・期限」を共有する
  （`PHASE_DATE_WINDOWS`、決算準備＝決算日の2ヶ月前〜決算日、申告・納税＝決算日〜
  決算日の2ヶ月後。`addMonths_` in `DateUtils.gs`で計算）。進捗はそれぞれ
  未着手/対応中/完了のシンプルな3段階のみで管理する。生成後は案件ごとに個別編集できる
  （テンプレート＋個別調整のハイブリッド方式）。
- **色分け判定**（`StatusService.gs`）: 案件全体のステータスは決算日基準の3段階判定のみ
  （通常/要注意/遅延、要件定義書3.5）。タスク一覧の行の背景色（うっすら赤/黄）は、
  そのタスク自身の期限による判定（手動上書き`manualOverride`可）。この2つは独立しており、
  個別タスクが期限切れでも案件全体のステータスには影響しない（自動生成された初期タスクの
  期限が、同期直後で未着手のまま経過していることは珍しくないため、それだけで案件全体を
  「遅延」扱いにしないための仕様）。
- **基準日**: ダッシュボード右上の「基準日」欄で日付を指定すると、その日付を
  「今日」とみなしてステータス判定をやり直せる（例：1ヶ月後の時点でどの案件が
  要注意になるか事前確認する、など）。未指定時は実際の今日の日付を使う。
  `getDashboardData` / `runSyncAndGetDashboardData` / `saveTaskUpdate`（`Code.gs`）が
  それぞれ `referenceDateIso` 引数を受け取る。
- **年間カレンダービュー**（`AnnualService.gs`）: ダッシュボード最上部に、指定した年
  （1/1〜12/31、既定は今年）を1画面で見渡せるガントチャートを表示する。
  - 顧客ごとに「準備期間」（決算日を含む2ヶ月間。例: 8月末決算なら7月〜8月末）と
    「決算期間」（決算日の直後2ヶ月間。例: 9月〜10月末）をそれぞれ別の色のバーで表示する。
  - 年の範囲をまたぐ期間は表示年の1/1〜12/31にクリップされる（例えば12月決算の
    準備期間は前年11月分にあたるが、表示上は当年1/1からになる）。
  - チャート上部には、確定申告（1/1〜3/15）・法定調書・算定基礎届・年末調整など、
    法人・個人が一般的に対応する行事をマイルストンとして参考表示する
    （`Constants.gs` の `ANNUAL_MILESTONES`）。ただし実際の期限は企業・個人ごとに
    異なるため、あくまで目安。
  - マイルストンは、対象年・翌年分あわせて最大14件（7種類×2年）あるが、
    frappe-gantt側には1件も渡していない（1マイルストン=1行になり縦に長くなり
    すぎるため）。代わりに`renderMilestoneStrip`（`JavaScript.html`）が、
    顧客のガントチャートより上に、貪欲法の区間スケジューリング（開始日順に並べ、
    既に終わっている行があればそこに詰める）で自前のコンパクトな帯を描画する。
    重複しないマイルストン同士は同じ行に詰められるため、実際に必要な行数は
    2〜3行程度で済む（各ブロックにマウスを乗せると正式名称と期間がツールチップで
    出る。横幅が狭いブロックは名称が省略表示になることがある）。
- **「季節内」フィルター**（`isInSeason` in `JavaScript.html`）: タスク一覧・年間カレンダー
  とも、基準日の月を中心に前後2ヶ月（例: 基準日が8月なら6月〜10月決算）に決算日が
  入っている顧客だけを対象にする。決算がまだ遠い顧客のノイズを削り、
  「今まさに動きがある顧客」だけに絞り込むための共通ルール。
- **タスク一覧**（`renderActionPanel` in `JavaScript.html`）: 「季節内」の顧客が持つ
  タスク（サブタスク5件×案件数）を、スプレッドシートの一覧表に近い、
  1行1タスクの密な表で表示する（フェーズ/タスク/クライアント名/決算期/担当者/
  開始/期限/ステータス/コメント）。担当者による絞り込みも、専用の全体フィルターは
  設けず、この表自身の列フィルターの1つとして提供している。
  - 列見出し下のプルダウン（フェーズ・タスク・クライアント名・決算期・担当者・
    ステータス）で絞り込める。フェーズは決算準備/申告・納税の大区分、タスクは
    個々のサブタスク名での絞り込み。決算期の選択肢は日付順（文字列順ではない）で
    並ぶ（`uniqueFiscalPeriods` in `JavaScript.html`）。
  - 決算期列には、その案件の決算年月を「20XX年X月期」の形式で表示する
    （`formatFiscalPeriod` in `JavaScript.html`）。
  - ステータス列は編集可能なプルダウンで、選択するとその場で保存される
    （未着手=グレー/対応中=オレンジ/完了=濃紺の色付き）。
  - 担当者は名前ごとに色分けしたチップで表示（読み取り専用。担当者は顧客マスタ側の
    情報で、タスク単位では変更できないため）。
  - コメント欄は自由入力で、入力するたびに自動保存される（保存タイミングは後述の
    バッチ保存を参照。フォーカスを外さなくても、入力が一定時間止まれば保存される）。
  - フェーズ列（決算準備/申告・納税）をクリックすると、期限や進捗を細かく調整できる
    編集モーダルが開く。
  - 行の色分け（`rowStatusClass` in `JavaScript.html`）: ステータスが完了の行は
    グレーアウトする（`row-done`）。未完了のまま期限（そのタスクの期日）が基準日を
    過ぎている行は薄い赤で示す（`row-overdue`）。両方の条件を満たす場合は完了が
    優先される。
  - 現在のフィルター条件に一致するタスクが0件になっても、表自体（列見出しの
    プルダウン）は表示したままにする。0件は本文エリアのメッセージ
    （「該当するタスクはありません」）だけで示すので、フィルターを変更して
    元に戻すことができる。
- **年間カレンダーの「今日」ライン**: 基準日の位置に赤い縦線を表示する。frappe-gantt
  0.6.1には任意の日付に対応した「今日」表示機能がないため、その日1日だけの非表示タスク
  （`type-today-marker`、CSSで`opacity:0`）を紛れ込ませてライブラリ自身に位置計算させ、
  その結果のx座標を読み取って自前の`<line>`を重ねる、という手法で実現している
  （`drawTodayLine` in `JavaScript.html`）。
- **年間カレンダーの行の統合**: 同じ決算日の顧客同士は、準備期間・決算期間それぞれの
  バーを1本にまとめ、顧客名を「、」区切りで連結して表示する（例:
  「合同会社B、株式会社D（準備期間）」）。52社分を1顧客1行で並べると縦に長くなりすぎる
  ため、同じ期間を共有する顧客をまとめて行数を抑えている。
- **年間カレンダーのマイルストン期間**: `getAnnualCalendarData`（`AnnualService.gs`）は
  マイルストンだけ「対象年」と「対象年+1」の2年分を返す（顧客の準備期間/決算期間の
  バーは従来どおり対象年の1/1〜12/31にクリップされたまま）。基準日には依存しないので、
  対象年を切り替えなくても翌年の確定申告・年末調整などが常に見える。翌年分の名前には
  「（20XX年）」を付けて区別する。
- **同期の二重実行対策**（`syncTasksFromCustomers` in `TaskService.gs`）: このアプリは
  10名規模で共有するため、複数人がほぼ同時に「スプレッドシートと同期」を押す、または
  同じ人が連打する可能性がある。`ensureTasksForCustomer_` の重複チェックは同期処理の
  先頭で1回だけ取得したスナップショットに対して行われるため、ロックなしで同時に2つの
  同期が走ると、両方とも「まだ生成されていない」と判定してしまい、同じ案件のタスクが
  2倍に生成されるバグがあった。`LockService.getScriptLock()` で同期処理全体を排他化し、
  常に1つずつ順番に実行されるようにして修正した。あわせてクライアント側でも
  「スプレッドシートと同期」ボタンをリクエスト中は無効化している（`JavaScript.html`）。
  この修正より前に発生した重複タスクは自動では解消されないため、後述の
  `deduplicateTasks` を実行して解消すること。
- **インライン編集のバッチ保存**（`queueTaskUpdate` / `flushPendingUpdates` in
  `JavaScript.html`、`saveTaskUpdatesBatch` in `Code.gs`、`updateTasksBatch_` in
  `TaskService.gs`）: タスク一覧のステータス・コメントを編集するたびに個別に
  サーバーへ送信して画面全体を「更新中」で覆う、という以前の挙動をやめ、変更を
  いったんブラウザ側にためておき（画面には即座に反映される）、入力が1秒止まった
  タイミングでまとめて1回のリクエスト（`saveTaskUpdatesBatch`）で送信するように
  変更した。複数行・複数項目を続けて編集しても、サーバーへの往復は1回にまとまる。
  画面右上の「未保存の変更があります…」「保存中…」「保存しました」の表示で
  保存状況を確認できる。画面全体を覆うローディングは、初回読み込み・「同期」
  ボタン・編集モーダルからの保存など、まとまった操作のときだけに限定した。
  基準日の変更やページを閉じる直前には、たまっている変更を先に送信してから
  次の処理に進む。
- **重複データの手動クリーンアップ**（`deduplicateTasks` in `TaskService.gs`）:
  上記の同期二重実行バグなどで既にタスクが重複してしまっている場合に、
  Apps Scriptエディタの関数選択プルダウンで `deduplicateTasks` を選び、
  上部の実行ボタン（▷）で1回だけ手動実行する。同じ案件・決算日・フェーズの
  行が複数あれば、最初の1件だけ残して残りを削除する（`resetAllTasks` と違い、
  残す行の進捗・コメントはそのまま保持される）。
- **デプロイ確認用のバージョン表示**（`APP_VERSION` in `Constants.gs`）:
  画面最下部に表示される「バージョン: yyyy-mm-dd.n」は、コード変更のたびに
  更新される目印。このアプリはGitHub上のコードを直接実行しているわけではなく、
  Apps Scriptエディタに貼り付けた内容がそのまま動くため、ファイルの貼り替えが
  一部抜けていると、修正したはずの不具合が「直っていない」ように見えることが
  ある。動作がおかしいときは、まず画面最下部のバージョンが、渡された手順書の
  バージョンと一致しているか確認し、一致していなければ該当ファイルを貼り直す。

## 既知の落とし穴（frappe-gantt関連）

- CDNから読み込むファイルは `frappe-gantt.umd.js` **ではなく** `frappe-gantt.min.js`
  （または `frappe-gantt.js`）にすること。`.umd.js` はこのバージョンのパッケージに
  存在せず、404で `Gantt` が未定義のままガントチャートが一切描画されない
  （エラーも出ずに真っ白になるだけなので気づきにくい）。
- `new Gantt(...)` のオプションに `language: 'ja'` を渡さないこと。v0.6.1には
  日本語の月名データが同梱されておらず、内部で例外が発生してチャートが描画されない。
  言語オプションは省略し、英語表記（Month/Week名）のまま使う。

## ローカル開発

`clasp push` で `src/` 配下の `.gs` / `.html` / `appsscript.json` のみが同期される
（`.claspignore` 参照）。Claude Codeでコードを編集し、`clasp push` でGASに反映する運用を想定。
