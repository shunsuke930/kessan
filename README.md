# 決算対応タスク管理

税理士事務所向けの月次タスク自動抽出ツール（Google Apps Script製）。**Webアプリ
ではなく、スプレッドシートそのものが画面**になっている。既存の顧客管理
スプレッドシートを読み取り専用で参照し、「今月対応が必要な会社」を自動抽出して
専用シート（既定では `案件タスク` タブ）に書き出す。進捗（ステータス）・
コメントはそのシートのセルに直接入力する。

以前はWebアプリ（ブラウザで開く専用画面）として作っていたが、①毎回の
「デプロイ」作業が事故の元になりやすい、②スタッフは全員スプレッドシートの
操作に慣れている、という2点から、**表示・編集ともにスプレッドシートへ完全移行
した**。これにより、コードを直しても「デプロイし直す」という手順は一切不要になり
（Apps Scriptエディタで保存すれば即座に反映される）、URLへのアクセス権限設定も
不要になった。

## ディレクトリ構成

```
src/
  appsscript.json      GASマニフェスト
  Constants.gs          設定・月次タスク抽出ルール（TASK_RULES）の定義
  DateUtils.gs          日付ユーティリティ
  CustomerService.gs    顧客マスタシートの読み取り（読み取り専用）
  TaskService.gs        タスクシートの同期・整形ロジック（表示もこのシートが担う）
  Menu.gs                スプレッドシートのカスタムメニュー・onEdit/自動更新トリガー
```

## セットアップ

Webアプリ版と違い、**「デプロイ」という手順そのものが存在しない**。以下の
手順だけで完結する。

### 1. スクリプトを紐づけるスプレッドシートを決める

一番シンプルなのは、既存の顧客管理スプレッドシートに `案件タスク` という
新しいタブを追加し、そのスプレッドシート自体にスクリプトを紐づける方法
（この場合、後述のスクリプトプロパティは1つも設定しなくてよい）。
既存シートに触れたくない場合は、別の新規スプレッドシートを用意し、
そちらにスクリプトを紐づけてもよい（その場合は `CUSTOMER_SPREADSHEET_ID` に
既存シートのIDを設定する）。

### 2. Apps Scriptエディタを開いてコードを貼り付ける

1. 紐づけると決めたスプレッドシートを開く
2. メニューの「拡張機能」→「Apps Script」
3. 左のファイル一覧で、`src/` 配下の各ファイル（`Constants.gs` /
   `DateUtils.gs` / `CustomerService.gs` / `TaskService.gs` / `Menu.gs`）と
   同名のファイルを作成し（＋ボタン）、それぞれの中身をこのリポジトリの内容で
   丸ごと置き換える。デフォルトで存在する `コード.gs`（`Code.gs`相当）は
   空にするか削除してよい（今回使わない）
4. `appsscript.json` の内容も差し替える（表示されない場合は、Apps Script
   エディタの歯車アイコン「プロジェクトの設定」→「"appsscript.json"
   マニフェスト ファイルをエディタで表示する」にチェック）
5. 全ファイルを保存（Ctrl+S / Cmd+S）

### 3. スクリプトプロパティの設定（別スプレッドシートに分ける場合のみ）

顧客マスタと `案件タスク` を同じスプレッドシートにする場合は、**この手順は
不要**（何も設定しなければ、このスクリプトが紐づいているスプレッドシート自身を
自動的に使う）。分ける場合のみ、Apps Scriptエディタの「プロジェクトの設定」→
「スクリプト プロパティ」から設定する。

| プロパティ名 | 必須 | 内容 |
|---|---|---|
| `CUSTOMER_SPREADSHEET_ID` | 分ける場合は必須 | 既存の顧客管理スプレッドシートのID（URLの `/d/` と `/edit` の間） |
| `CUSTOMER_SHEET_NAME` | 任意 | 顧客一覧のシート名。未設定時は先頭シートを使用 |
| `TASKS_SPREADSHEET_ID` | 任意 | タスクデータの保存先スプレッドシートID。未設定時は顧客マスタと同じファイルを使う |
| `TASKS_SHEET_NAME` | 任意 | タスク用タブ名。既定値 `案件タスク` |

### 4. 顧客マスタの列名の確認・調整

`src/Constants.gs` の `CUSTOMER_COLUMN_ALIASES` は以下の見出し候補を自動検出する：

- 顧客名（法人名・会社名も同じ列として扱う）: `顧客名` / `法人名` / `会社名`
- 決算月: `決算月`
- 決算日: `決算日`
- 担当者: `担当者`

`顧客名`列と、`決算月`または`決算日`のどちらか一方の列があれば動作する
（両方あれば`決算日`を優先し、`決算日`が空の行は`決算月`の末日から自動計算する）。
実際のシートの見出しがこれと異なる場合は、`CUSTOMER_COLUMN_ALIASES` に候補を追加する。

### 5. スプレッドシートを再読み込みしてメニューを表示

保存が終わったら、スプレッドシートのタブを再読み込み（F5 / Cmd+R）する。
上部のメニューバーに **「決算タスク管理」** という新しいメニューが追加される
（表示されない場合は、もう一度読み込み直す）。

### 6. 初期セットアップを実行

「決算タスク管理」メニュー →「シートの表示設定を初期化」をクリック。
初回はGoogleの権限確認画面が出るので、自分のアカウントを選び、
「このアプリは確認されていません」と出たら「詳細」→
「（プロジェクト名）に移動（安全ではないページ）」→「許可」で承認する
（自分で作ったスクリプトなので問題ない）。これで `案件タスク` シートに、
ステータスのプルダウンや色分けなどの表示設定が一括で適用される。

### 7. 今月のタスクを生成

「決算タスク管理」メニュー →「今月のタスクを更新」をクリック。今月対応が
必要な会社が `案件タスク` シートに一覧で追加される。

### 8. （推奨）毎月の自動更新を有効にする

「決算タスク管理」メニュー →「毎月1日の自動更新を有効にする」をクリックすると、
毎月1日の朝に自動で「今月のタスクを更新」が実行されるようになる。これを
やっておけば、月が変わるたびに手動でメニューを押す必要がなくなる
（後から「毎月1日の自動更新を無効にする」でいつでも止められる）。

## `案件タスク` シートの使い方

- **タスク・クライアント名・決算期・担当者**: 自動生成される列。手で編集しない。
- **ステータス**: プルダウンから `未着手` / `対応中` / `完了` を選ぶ。完了にすると
  その行全体がグレーアウトする。
- **コメント**: 自由入力。
- どちらを編集しても、裏側の「更新日時」列（非表示）が自動更新される。
- 対象月が過去で、かつステータスが完了でない行は薄い赤で表示される
  （対応漏れの見落とし防止）。
- 列見出しに絞り込み矢印が付いているので、タスク・クライアント名・担当者などで
  絞り込みたいときはそこから操作する（Googleスプレッドシート標準のフィルタ機能）。
- 過去の月のデータも消さずに下に積み上がっていく。「今月のタスクを更新」を
  実行すると、直近の対象月が常に一番上にくるよう並び替えられる。

## 決算タスク管理メニューの一覧

| メニュー項目 | 内容 |
|---|---|
| 今月のタスクを更新 | 今月対応が必要な会社の行を追加する（既存の行・進捗は変更しない） |
| 重複を削除 | 同じ会社・タスク・対象月の行が複数あるとき、最初の1件だけ残して削除する（進捗は保持） |
| シートの表示設定を初期化 | プルダウン・色分け・列の非表示などの表示設定を再適用する |
| 毎月1日の自動更新を有効/無効にする | 月初の自動更新トリガーのON/OFF |
| バージョン確認 | 貼り付けたコードのバージョンを表示する（貼り替え漏れの確認用） |
| 【注意】全データをリセット | `案件タスク` シートを空にして作り直す。**入力済みの進捗・コメントも消える** |

## 主要ロジックのメモ

- **月次タスク抽出ルール**（`Constants.gs` の `TASK_RULES`）: このツールは
  「月初にその月に対応が必要な会社を自動で一覧化する」もので、顧客ごとの決算
  サイクル全体を追うのではなく、対象月ごとに独立してリストを作る。各ルールは
  対象月から見て顧客の決算月が何ヶ月ずれているか（`monthOffsets`、複数指定可）
  で対象を抽出する。
  - **申告準備**（`monthOffsets: [1]`）: 決算月が対象月の1ヶ月後の会社（決算日の
    1ヶ月前 = 準備を始めるタイミング）
  - **申告・納税**（`monthOffsets: [-1, -2]`）: 決算月が対象月の1ヶ月前 または
    2ヶ月前の会社（日本の法人税申告・納税期限＝決算日から2ヶ月後なので、決算日の
    翌月・翌々月の2ヶ月間、一覧に出続ける）
  - **納税予想**（`monthOffsets: [6]`）: 決算月が対象月の6ヶ月後の会社
    （決算日の6ヶ月前＝事業年度のほぼ中間点。中間納付の見込みを立てる想定）
  - 判定は決算「月」のみで行う（`getMonthlyMatches_` in `TaskService.gs`）。日付は
    表示用の決算期（20XX年X月期）を出すためだけに使う。
- **同期は完全に冪等**（`ensureMonthlyTasks_` in `TaskService.gs`）: 同じ会社・
  タスク・対象月の組み合わせに対して行が既にあれば、何度「今月のタスクを更新」を
  実行しても新しい行は作られない（進捗・コメントも上書きされない）。複数人が
  ほぼ同時にメニューを押しても、`LockService` で排他制御しているため重複しない。
- **担当者・決算期の非正規化保存**: `案件タスク` シートの各行に、生成時点の
  担当者名・決算日をそのままコピーして保存している（顧客マスタへその都度
  問い合わせない）。スプレッドシートの表示だけで完結させるための単純化で、
  もし顧客マスタ側で担当者が変わっても、過去に生成済みの行の担当者表示は
  自動更新されない（該当行を手動で直すか、`resetAllTasks` で作り直す）。
- **行の色分け**（`setupSheetFormatting_` in `TaskService.gs`、条件付き書式）:
  ステータスが完了の行はグレーアウトする。対象月が実際の今月より過去で、かつ
  未完了の行は薄い赤で示す（対応漏れの見落とし防止）。
- **更新日時の自動記録**（`onEdit` in `Menu.gs`）: ステータスかコメントのセルを
  編集すると、同じ行の「更新日時」列（非表示）が自動更新される。
- **同期の二重実行対策**: 「今月のタスクを更新」は手動メニュー・毎月1日の
  自動トリガーの両方から呼ばれる可能性があるため、`LockService` で処理全体を
  排他化している。
- **`onOpen`/`onEdit` の権限制約**: スプレッドシートを開いたときやセルを編集した
  ときに自動で走るこの2つの関数は、Apps Scriptの制約で「認可なし」モードで実行
  され、別のスプレッドシートを開く（`SpreadsheetApp.openById`）といった操作が
  できない。そのため `onOpen` はメニューを作るだけにとどめ、実際のデータ同期
  （顧客マスタが別ファイルの場合はそれを開く必要がある）は、メニュークリックや
  毎月1日の時間主導トリガーなど、ユーザー操作を伴う「認可あり」のタイミングでしか
  呼ばないようにしている。
- **重複データの手動クリーンアップ**（`deduplicateTasks` in `TaskService.gs`）:
  何らかの理由でタスクが重複してしまった場合に、メニューの「重複を削除」で
  解消できる（`resetAllTasks` と違い、残す行の進捗・コメントはそのまま保持される）。
- **バージョン確認**（`APP_VERSION` in `Constants.gs`）: メニューの「バージョン
  確認」で、貼り付けたコードのバージョンを表示できる。複数ファイルを貼り替える
  作業では、一部のファイルだけ貼り替えが漏れることがあるため、渡された手順書の
  バージョンと一致しているか確認する用途に使う。

## ローカル開発

`clasp push` で `src/` 配下の `.gs` / `appsscript.json` のみが同期される
（`.claspignore` 参照）。Claude Codeでコードを編集し、`clasp push` でGASに
反映する運用を想定。ただし今回のスプレッドシート常駐型では、`clasp` を使わず
Apps Scriptエディタへの直接貼り付けで運用することも多いため、ファイルの
貼り替え手順は上記「セットアップ」を参照。
